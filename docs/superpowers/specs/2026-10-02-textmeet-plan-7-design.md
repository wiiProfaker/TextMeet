# TextMeet — План 7 (каталог моделей расшифровки): решения

**Дата:** 2026-10-02
**Основа:** [спецификация](2026-09-25-textmeet-design.md) §3.3, §3.6, §5.4, §5.5, §6; [решения Плана 3](2026-09-29-textmeet-plan-3-design.md)
(конвейер, очередь, менеджер моделей); [проверки Плана 3](../plan-3-checks.md); [макет](https://claude.ai/artifact/Urmc3atvSFifUpDyBzjeR6)
(лист 6 — настройки «Расшифровка»).
**Согласовано с пользователем 2026-10-02:**
- Другая модель нужна «просто для выбора» — жалобы на GigaAM нет.
- Нужен **каталог моделей, как в программе Handy** (пользователь прислал снимок экрана): карточки с языками, размером,
  полосками «точность» и «скорость», кнопками «Скачать» / «Удалить»; пользователь сам решает, что скачать.
- В каталоге — модели, понимающие русский, **и** модели только для английского.
- Кнопки «Добавить свой файл модели» **нет** — хватит каталога; новую модель в каталог добавляем по просьбе.
- Все модели работают **на процессоре** (как GigaAM); ускорение на видеокарте — потом, отдельным планом.
- Модель выбирается в настройках (для новых встреч) **и** в окне «Расшифровать заново» (для одной встречи); во встрече
  подписано, какой моделью сделан текст.

Первые версии этого документа (Whisper через whisper.cpp и свои файлы ggml) отменены: каталог проще и даёт больше
выбора. Всё работает на том же движке sherpa-onnx, что и GigaAM, — новой программы рядом с TextMeet не появляется.

## 1. Что входит в План 7

- Каталог моделей в коде: GigaAM v3 (как сейчас) + новые (§3). Скачивание и удаление по карточке.
- Распознаватель для каждого вида моделей (sherpa-onnx: transducer NeMo, Qwen3-ASR, Whisper, Canary, Moonshine,
  потоковые T-one и Nemotron) за общим интерфейсом `Recognizer`.
- Раздел настроек «Расшифровка» в виде каталога; выбор модели в «Расшифровать заново»; подпись модели во встрече.
- Замер скорости каждой модели на ПК пользователя (прототип) → полоска «скорость»; «точность» — по опубликованным
  замерам и прототипу.

**Не входит:** видеокарта; свои файлы моделей; выбор языка (§4.2); выбор модели ИИ (План 6); правка текста, поиск
(План 4).

## 2. Интерфейс

- **Настройки → «Расшифровка»** — каталог, как на снимке Handy, в стиле «Бумага»:
  - Сверху — **«Выбрана»**: карточка текущей модели.
  - **«Скачанные»** — карточки скачанных моделей; кнопки «Выбрать» и «Удалить».
  - **«Доступны для загрузки»** — две группы: **«Понимают русский»** и **«Только английский»**; кнопка «Скачать».
  - **Карточка:** название и автор («Parakeet v3 · NVIDIA»), одна строка описания, языки («Только русский» /
    «25 языков» / «Только английский»), размер, полоски «точность» и «скорость» (5 делений), пометка
    «Рекомендуется» — только у GigaAM v3. Во время скачивания — полоса «Скачиваем — 120 из 464 МБ» и «Отменить».
  - Одновременно скачивается одна модель (как в Плане 3); остальные кнопки «Скачать» ждут.
  - «Удалить» недоступно, пока идёт расшифровка (как в Плане 3). Удалить выбранную модель → выбор возвращается к
    GigaAM v3. Удалить GigaAM v3 можно — она скачается заново при следующей расшифровке, если выбрана.
  - Строка «Разделение по голосам и поиск речи · 33 МБ» с «Удалить» — внизу раздела, как в Плане 3.
- **Модели только для английского** помечены в карточке и в выборе: «Только английский — русская речь распознается
  неверно».
- **Во встрече.** Под заголовком (рядом с датой и длительностью) — «Текст: GigaAM v3» / «Текст: Parakeet v3» и т. д.
  Название запоминается в тексте встречи — подпись остаётся и после удаления модели.
- **«Расшифровать заново».** Над вопросом о числе участников — «Модель» (выпадающий список: **все модели каталога**,
  нескачанные — с пометкой «скачается, 464 МБ»), по умолчанию — выбранная в настройках. Встреча расшифровывается
  выбранной; настройка не меняется.
- **«Расшифровать», «Повторить», окно «Запись остановлена»** — модель из настроек на момент постановки в очередь.
- **Прогресс встречи** — как в Плане 3; на этапе скачивания — название модели: «Скачиваем модель Parakeet v3 — 120 из
  464 МБ».

## 3. Каталог

| Модель | Автор | Языки | Размер* | Вид в sherpa-onnx |
|---|---|---|---|---|
| **GigaAM v3** (выбрана по умолчанию) | Сбер | русский | 330 МБ | transducer (как сейчас) |
| **Parakeet v3** | NVIDIA | 25 европейских, вкл. русский и английский | 464 МБ | transducer NeMo |
| **Qwen3-ASR 0.6B** | Alibaba | 30 языков | 837 МБ | qwen3Asr |
| **Whisper large-v3-turbo** | OpenAI | ~100 языков | 537 МБ | whisper |
| **Nemotron 3.5** | NVIDIA | 40 языков | 453 МБ | потоковый transducer |
| **T-one** | Т-Банк | русский (обучена на телефонных разговорах) | 122 МБ | потоковый toneCtc |
| **Parakeet Unified EN 0.6B** | NVIDIA | английский | 478 МБ | transducer NeMo |
| **Canary 180M Flash** | NVIDIA | английский, испанский, немецкий, французский | 146 МБ | canary |
| **Moonshine Base** | Useful Sensors | английский | 106 МБ | moonshine |

\* Размер архива в выпуске sherpa-onnx; точный размер файлов — в реестре (прототип).

- **Источник файлов:** отдельные файлы с Hugging Face (зеркала моделей sherpa-onnx, у каждого файла есть размер и
  SHA-256 — тот же скачиватель, что у GigaAM, без распаковки архивов). Если у модели нет зеркала с отдельными
  файлами — архив `.tar.bz2` из выпуска `asr-models` sherpa-onnx: SHA-256 архива → распаковка нужных файлов →
  метка `installed.json`. Что из двух — решается для каждой модели при написании плана.
- **Попадание в каталог** — только после прототипа: модель загружается в `sherpa-onnx-node` 1.13.8 на Windows и
  Mac (CI), распознаёт эталонную запись, текст разумный. Не прошедшая проверку модель в каталог не попадает, и
  пользователю об этом сообщается (особый риск — Nemotron 3.5: в `sherpa-onnx-node` не видно настройки языка).
- **Полоски.** «Скорость» — по скорости на записи из `TextMeet-samples` на ПК пользователя (RTF, 5 делений: ≤ 0,05 …
  > 0,5). «Точность» — по опубликованным замерам на русском (у английских — на английском) и прочтению текста
  прототипа; 5 делений. Числа — в каталоге в коде, с источником в комментарии.

## 4. Как это работает

### 4.1 Распознаватели
- Интерфейс `Recognizer` (План 3) не меняется: `recognize(samples): string`. Конвейер (детектор речи, разделение по
  голосам, резка ≤ 20 с) — как в Плане 3, для всех моделей.
- Каталог описывает модель данными: id, название, автор, описание, языки, группа (`ru` / `en`), полоски, файлы, вид и
  параметры для sherpa-onnx. Фабрика распознавателей по виду строит `OfflineRecognizer` / `OnlineRecognizer`
  (для потоковых: кусок подаётся целиком, затем `inputFinished`, затем декодирование до конца — это тот же «кусок →
  текст»).
- Резка ≤ 20 с подходит всем видам (у Whisper окно 30 с; у остальных ограничений короче 20 с нет — прототип
  подтверждает).
- Процесс расшифровки держит один распознаватель (кеш размера 1, как в Плане 3): смена модели между встречами
  освобождает прежнюю.

### 4.2 Язык
- Многоязычные модели работают с **автоопределением языка** (Whisper, Qwen3-ASR, Nemotron, Canary — там, где
  sherpa-onnx его даёт), чтобы те же модели годились и для встреч на английском. Прототип проверяет на русской записи,
  что автоопределение не путает язык на коротких кусках; если путает — для этой модели закрепляется русский.
- Модели только для английского язык не спрашивают.

### 4.3 «Галлюцинации» Whisper и Qwen3
На шуме они дописывают «Продолжение следует…», «Субтитры сделал …», «Спасибо за просмотр» и зацикливаются. Защита
(для всех моделей, безвредна для остальных): куски уже нарезаны детектором речи; текст куска, целиком совпадающий (без
регистра и знаков) с фразой из списка известных, отбрасывается; одна и та же фраза из 1–8 слов подряд больше 3 раз
обрезается до одного раза. Список — в коде, с тестами.

### 4.4 Скорость и нагрузка
Как в Плане 3: приоритет ниже обычного, потоки `min(8, ядер − 1)`, во время записи — 2. Медленные модели (Whisper,
Qwen3) на часе записи могут работать десятки минут — это видно по полоске «скорость» в карточке до скачивания.
Сторож зависания (План 3 §5.2) учитывает скорость модели: срок умножается на отношение её RTF к RTF GigaAM (из
каталога).

## 5. Данные

- **`settings.json`** — новое поле `asrModel` (id из каталога, `.default('gigaam-v3-e2e-rnnt')`); неизвестный id
  читается как GigaAM.
- **`TranscribeRequest`** получает `model: string | null` (null — из настроек).
- **`meeting.json`** — поле `model` уже есть (План 3): id модели этой расшифровки. Очередь, продолжающаяся после
  перезапуска, берёт модель отсюда.
- **`transcript.json`** — `model` (id) уже есть; новое необязательное поле `modelTitle` (название на момент
  расшифровки) — для подписи во встрече. Старые тексты без него подписываются по каталогу («GigaAM v3»).
- **Модели на диске** — в той же папке моделей, по папке на модель; группа «voices» (разделение по голосам и поиск
  речи) — общая для всех.
- **Состояние каталога для окна:** для каждой модели — скачана / скачивается (байты) / нет; выбранная; идёт ли
  расшифровка.

## 6. Ошибки

| Ситуация | Что видит пользователь |
|---|---|
| Не скачалась модель | В карточке: «Не удалось скачать: нет связи с сервером» + «Повторить»; во встрече — как в Плане 3 |
| Файл повреждён (сумма / архив) | «Файл модели повреждён, он будет скачан заново» + «Повторить» |
| Мало места | «Не хватает места на диске для модели (нужно 837 МБ)» |
| Модель не загрузилась в движок | Встреча `error` «Не удалось загрузить модель „<название>“» + «Повторить»; подробности — в журнал |
| Встреча ставится на английскую модель | Без ошибки; в выборе и карточке — пометка «Только английский» |
| Модель встречи пропала из каталога (новая версия программы) | Расшифровка — GigaAM v3, в журнал — запись |

## 7. Тестирование

- **Модульные (Vitest):** каталог (уникальные id, у каждой модели есть файлы, размеры и суммы, полоски 1–5, группы);
  выбор файлов по модели; настройки (старый файл, неизвестный id → GigaAM); фабрика распознавателей — какой конфиг
  sherpa-onnx строится для каждого вида (без нативного кода); распаковка архива (неверная сумма, битый архив,
  `installed.json`); фильтр «галлюцинаций»; очередь с моделью задачи; состояние каталога (скачивание, отмена, удаление
  выбранной → GigaAM).
- **С настоящими моделями** (локально и в `ci` с кешем): каждая модель каталога распознаёт эталонную запись (русскую —
  русские, английскую — английские) — в `ci` на Linux, в `build.yml` — на Windows и Mac; это и есть проверка
  «модель работает на обеих ОС».
- **Сквозные (Playwright, подменный движок):** каталог в настройках, «Скачать» (подменный сервер) → «Выбрать» →
  «Расшифровать» → «Текст: <название>»; «Расшифровать заново» с другой моделью; «Удалить» выбранной → выбрана GigaAM.
- **Прототип на этом ПК:** все модели на записи из `TextMeet-samples` — скорость (для полосок) и тексты (для
  «точности» и проверки автоопределения языка).
- **Ручная проверка** на Windows и Mac: скачать 2–3 модели, расшифровать одну встречу разными моделями через
  «Расшифровать заново», удалить модель, выход во время скачивания.
