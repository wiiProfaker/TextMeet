# TextMeet — План 6 («Скопировать для ИИ»): решения

**Дата:** 2026-10-11
**Основа:** [спецификация](2026-09-25-textmeet-design.md) §3.5, §3.6; [макет](https://claude.ai/artifact/Urmc3atvSFifUpDyBzjeR6),
лист 1 (кнопка «Скопировать для ИИ» в шапке встречи) и лист 6 (раздел «ИИ» в настройках — меняется, см. §2.2).
**Согласовано с пользователем 2026-10-11:**

- Ключа API нет и заводить его пользователь не планирует; подписка — Claude Pro, позже, возможно, ChatGPT.
- Сначала обсуждали ответы ИИ прямо в программе через установленные Claude Code и Codex (за счёт подписки). Затем
  пользователь решил: **подключать облачный ИИ из программы не нужно** — достаточно скопировать текст и самому вставить
  его в Claude, ChatGPT или любой другой чат.
- Итоги прямо в TextMeet будет делать **локальная модель** — отдельным **Планом 9** сразу после этого плана. В него
  переходит одобренный пользователем блок итогов во встрече (§5).
- Интерфейс и текст стандартного запроса (§2) пользователь одобрил: «да».

## 1. Что входит в План 6

- Кнопка «Скопировать для ИИ» в шапке встречи: копирует запрос и текст встречи простым текстом.
- Раздел «ИИ» в настройках: поле «Запрос для ИИ» и ссылка «Вернуть стандартный».

**Не входит:** подключение Claude и ChatGPT из программы (ключом API или через подписку) — убрано из спецификации;
итоги и вопросы к встрече внутри программы, `ai.json`, итоги в поиске и в выгрузке — План 9 (локальная модель);
набор нескольких запросов (шаблонов) — спецификация §4; открытие сайта чата после копирования.

## 2. Интерфейс

### 2.1 Встреча (лист 1)

- В шапке встречи кнопка **«Скопировать для ИИ»** — слева от «Экспорта» (как на листе 1; «Итоги встречи» с листа 1
  появится в Плане 9). Видна тогда же, когда «Экспорт»: у встречи есть текст хотя бы в одной реплике.
- Нажатие копирует в буфер обмена (§3.2). Кнопка на 2 секунды становится «✓ Скопировано», как «Экспорт» после
  «Скопировать всё»; экранному диктору — «Текст встречи с запросом скопирован». Повторное нажатие снова показывает
  «Скопировано» на 2 секунды.
- Не удалось прочитать текст — та же строка ошибки слева, что у «Скопировать всё» («Не удалось прочитать текст
  встречи.» / «У встречи пока нет текста — выгружать нечего.»).

### 2.2 Настройки → «ИИ» (лист 6, изменённый)

Раздел **«ИИ»** между «Расшифровкой» и «Общими». На листе 6 в нём сервис, ключ API и модель — их нет. Остаётся одно поле:

- **«Запрос для ИИ»** — многострочное поле, в котором стоит стандартный запрос (§2.3); его можно переписать как угодно
  (до 4000 символов) — копироваться будет ваш текст.
- Под полем подсказка: «Добавляется перед текстом встречи, когда вы нажимаете „Скопировать для ИИ“. Вставьте
  скопированное в Claude, ChatGPT или другой чат.»
- Ссылка **«Вернуть стандартный»** — видна, только если запрос изменён; возвращает стандартный текст.
- Изменения сохраняются сами: через полсекунды после последней набранной буквы и при уходе из поля. Кнопки «Сохранить»
  нет, как и у остальных настроек.
- Пустое поле — запрос не добавляется, копируется только текст встречи.

### 2.3 Стандартный запрос

```
Ниже — расшифровка встречи, сделанная автоматически: в ней могут быть ошибки распознавания. «Я» — это я, «Спикер 2»,
«Спикер 3» — участники, чьи имена неизвестны.
Сделай итоги встречи по-русски, кратко:
— 3–5 главных пунктов;
— принятые решения;
— задачи: кто, что, к какому сроку;
— открытые вопросы.
```

(В программе — те же строки, без переносов внутри первого предложения: перенос здесь только из-за ширины документа.)

## 3. Устройство

### 3.1 Настройки (`shared/settings.ts`)

- Новое поле `aiPrompt: string | null`, по умолчанию `null`.
  - `null` — стандартный запрос. Если в новой версии программы стандартный текст улучшится, у пользователя, который
    его не менял, он обновится сам.
  - `''` — запрос очищен: копируется только текст встречи.
  - строка до 4000 символов — свой запрос.
- Испорченное значение (не строка, длиннее 4000) забывается (`.catch(null)`), остальные настройки не сбрасываются —
  как у `asrModel` и `exportDir`. `schemaVersion` не меняется.
- Стандартный текст — константа `DEFAULT_AI_PROMPT` в `shared/ai-prompt.ts` (окну нужен для поля, main — для
  копирования); там же `AI_PROMPT_MAX = 4000` и `resolveAiPrompt(aiPrompt)` → текст запроса.
- Канал `settings:set-ai-prompt` (`string | null`, проверка zod: строка не длиннее 4000 или `null`). Main сохраняет
  настройки и возвращает их новое состояние, как остальные `settings:set-*`. Если окно присылает текст, равный стандартному,
  сохраняется `null`.

### 3.2 Копирование (`main/export/export-meeting.ts`)

- Канал `export:copy-for-ai` (`meetingId`, проверка как у `export:copy`).
- `copyForAi(deps, meetingId)`: тот же `loadDoc`, что у «Скопировать всё» (те же ошибки); запрос читается из настроек
  после уже начатых сохранений настроек (`SettingsStore.settled()`) — запрос, набранный перед уходом из настроек,
  успевает попасть в копию; затем текст:
  - запрос (обрезанный по краям), пустая строка, `toPlainText(doc)` — название, дата и длительность, участники,
    абзацы «Имя [время]» + текст;
  - если запрос пустой — только `toPlainText(doc)`.
- В буфер кладётся **только простой текст** (без html): чаты вставляют его без лишнего оформления. Переводы строк —
  `\n` на обеих системах (чаты в браузере их понимают).
- `copyMeeting` («Скопировать всё») не меняется.

### 3.3 Окно

- `CopyForAiButton.tsx` — кнопка с состоянием «Скопировано» (2 с), как у `ExportMenu`. Общий кусок (таймер
  «Скопировано» и строка для диктора) выносится в хук `useCopiedFlag` в `hooks.ts`; `ExportMenu` переходит на него.
- `MeetingPane.tsx` показывает кнопку при `canExport`, перед `ExportMenu`.
- `AiSettings.tsx` — раздел «ИИ» в `SettingsPane.tsx`: `textarea` (`maxLength` 4000), подсказка, «Вернуть стандартный».
  Сохранение с задержкой 500 мс и при `blur`; при уходе со страницы настроек несохранённый текст отправляется сразу.
  Пока поле в фокусе, есть неотправленный текст или сохранение ещё не ответило, пришедшие от main настройки не
  перезаписывают текст в поле. Не сохранилось — текст остаётся в поле и уходит снова при следующем уходе из поля или со
  страницы; ошибка — на странице настроек, а если с неё уже ушли — в строке ошибки слева. Main пишет понятную причину:
  «Не удалось сохранить запрос для ИИ: …».

## 4. Ошибки

| Ситуация | Поведение |
|---|---|
| Не удалось прочитать текст встречи | Строка ошибки слева: «Не удалось прочитать текст встречи.» (как у «Скопировать всё») |
| У встречи нет текста | Кнопки нет; если текст пропал между показом и нажатием — «У встречи пока нет текста — выгружать нечего.» |
| Не удалось сохранить запрос | «Не удалось сохранить запрос для ИИ: …» на странице настроек (ушли с неё — в строке ошибки слева); набранный текст остаётся в поле и отправляется снова |

Текст запроса и текст встречи в журнал ошибок не пишутся.

## 5. План 9 «Локальная модель для итогов» (для дорожной карты)

Пользователь согласился, что это будет отдельный план сразу после Плана 6, перед доводкой. Что в него переходит:

- Блок ИИ во встрече, одобренный 2026-10-11:
  - кнопка «Итоги встречи»;
  - итоги над текстом встречи с подписью «модель · дата» и ссылками «Скопировать», «Обновить» (с вопросом «Заменить
    итоги?») и «Свернуть»;
  - пометка «текст встречи меняли после итогов»;
  - под итогами — свои вопросы списком, от старых к новым, у каждого «Скопировать» и «Удалить»;
  - внизу поле «Свой вопрос к встрече» и кнопка «Спросить»;
  - пока модель пишет — «Остановить»; одновременно идёт один запрос на всю программу; ответ дописывается, даже если
    уйти на другую встречу;
  - простое оформление ответа: списки, жирный, курсив;
  - итоги и ответы находятся поиском; итоги попадают в начало выгрузки (Word, .txt, «Скопировать всё»), вопросы — нет.
- Каталог локальных моделей в настройках «ИИ» (Скачать / Выбрать / Удалить), как каталог моделей расшифровки.
  Кандидаты с хорошим русским: GigaChat 3 Lightning, Qwen3, T-lite. В каталог попадают только модели, чьи итоги на
  реальных записях пользователь сочтёт годными (сравнение с итогами Claude, вставленными через «Скопировать для ИИ»).
- Запрос для итогов берётся из того же поля «Запрос для ИИ».

Ожидания, названные пользователю: итоги часовой встречи — 1–3 минуты на ПК (RTX 3070, 8 ГБ), качество ниже Claude;
модель 5–6 ГБ скачивается один раз.

## 6. Тестирование

- **Модульные:** схема настроек (`aiPrompt`: по умолчанию `null`, свой текст, пустая строка, испорченное значение не
  сбрасывает остальное, длиннее 4000 — забывается); `resolveAiPrompt`; `copyForAi` (запрос + пустая строка + текст,
  пустой запрос, ошибки чтения, нет текста); `storedAiPrompt` (тип и длина — `AiPromptSchema`, текст, равный
  стандартному, → `null`); `SettingsStore.settled()`. Компоненты окна (`useCopiedFlag`, `AiSettings`) — сквозными
  тестами: модульных тестов компонентов в проекте нет.
- **E2E (Playwright):** «Скопировать для ИИ» во встрече → в буфере стандартный запрос и текст; правка запроса в
  настройках → копируется новый (и сразу после ухода из настроек); очищенное поле → только текст; «Вернуть
  стандартный»; запрос, набранный перед уходом из настроек, сохранён; неудачное сохранение — текст в поле, повтор,
  ошибка после ухода; кнопки нет у встречи без текста.
- **Ручная проверка (Windows; Mac — после публикации вместе с Планом 5):** вставить скопированное в Claude и ChatGPT
  (или другой чат) и получить итоги; поменять запрос, перезапустить программу — запрос сохранился.

## 9. Дополнено 2026-10-12: шестерёнка и вкладки настроек

После проверки Плана 6 на Windows пользователь попросил значок настроек — шестерёнку и настройки разделами, а не на
одной странице; выбрал вкладки сверху.

- Значок кнопки «Настройки» внизу слева — шестерёнка.
- Под заголовком «Настройки» — вкладки **Запись · Расшифровка · ИИ · Общие** (ARIA tabs: ←/→ по кругу, Home/End; в
  строке вкладок клавишей Tab попадаешь на выбранную). Заголовки разделов внутри вкладок убраны. Версия и путь к
  журналу — на вкладке «Общие». Строка ошибки настроек — над вкладками.
- Открытую вкладку помнит главное окно, пока программа запущена; после запуска — «Запись».
- На странице все четыре вкладки, видна одна (`hidden`): набранный запрос, каталог моделей и его сообщения не теряются
  при переключении. Ушли с вкладки «Запись», не закончив ввод горячей клавиши, — ввод отменяется, действующая
  комбинация возвращается.
