# TextMeet — спецификация (дизайн)

**Дата:** 2026-09-25
**Статус:** согласовано с пользователем в интервью, ждёт ревью документа
**Для кого:** только для владельца (Windows-ПК + Mac), не для публичного распространения

## 1. Цель

Небольшое настольное приложение для Windows и macOS, которое записывает встречи (онлайн-созвоны и живые),
локально расшифровывает запись в текст с разделением по спикерам, хранит библиотеку встреч с поиском
и по кнопке делает ИИ-итоги встречи.

Основной язык встреч — русский, иногда проскакивают английские слова.

## 3. Функции первой версии

### 3.1 Запись
- Две раздельные дорожки: **микрофон** и **системный звук** (звук компьютера).
- Переключатель «Звук компьютера» (включён перед каждой записью). Выключен — пишется только микрофон (живая встреча,
  бывает редко). Действует на ближайшую запись, после неё снова включается сам; отдельной настройки нет.
- Выбор микрофона в настройках (по умолчанию — системный).
- Управление: главное окно (большая кнопка «Запись», таймер, два индикатора уровня: «Микрофон», «Звук компьютера»)
  **и** значок в трее / строке меню. Во время записи значок с красной точкой; меню: «Начать/Остановить запись»,
  «Открыть TextMeet», «Выход».
- **Горячая клавиша** (глобальная — работает, когда окно скрыто или поверх открыт созвон на весь экран):
  одна комбинация и запускает, и останавливает запись. По умолчанию **`Ctrl+Space` на Windows** и
  **`Option+Space` на macOS** (Electron `globalShortcut`: `Control+Space` / `Alt+Space`).
  - Обратная связь: короткий звук (разный для старта и стопа; звук старта — до начала записи, стопа — после),
    системное уведомление и значок в трее. Звук отключается в настройках.
  - Остановка клавишей ведёт себя как кнопка «Стоп»: открывается окно с диалогом «Сколько человек было…».
  - **Переназначение** в настройках: поле «Горячая клавиша записи» → «Изменить» → пользователь нажимает
    новую комбинацию → она сразу регистрируется и сохраняется. Правила:
    - разрешены комбинации хотя бы с одним из `Ctrl`, `Alt`/`Option`, `Win`/`Cmd` (плюс, при желании, `Shift`)
      и одиночные `F1`–`F24`;
    - запрещены одиночные буквы, цифры, пробел, Enter, Esc, Tab без модификатора и `Shift` + буква (это просто
      заглавная буква) — всё это сломало бы набор текста; понятное сообщение, почему нельзя;
    - если новую комбинацию не удалось зарегистрировать (занята другой программой) — сообщение сразу,
      старая комбинация остаётся действующей;
    - кнопка «Сбросить» возвращает значение по умолчанию для текущей ОС.
  - Если при запуске программы сохранённая комбинация занята (на Mac `Option+Space` по умолчанию используют
    Alfred, Raycast, ChatGPT), показывается уведомление, а в настройках — предупреждение «Комбинация занята
    другой программой».
  - Известное следствие: пока TextMeet запущен, эта комбинация не доходит до других программ
    (на Windows — Word/Excel, на Mac — ввод неразрывного пробела).
- **Автозапуск:** настройка «Запускать TextMeet при входе в систему» (по умолчанию включена) — программа стартует
  свёрнутой в трей, чтобы горячая клавиша работала сразу.
- Закрытие окна не останавливает запись и не выходит из программы (сворачивание в трей). Выход во время записи —
  с подтверждением.
- Напоминание: если обе дорожки молчат дольше 10 минут во время записи — системное уведомление
  «Запись всё ещё идёт». Автоостановки нет.
- Проверка свободного места перед стартом: предупреждение при < 1 ГБ (системным окном — старт бывает и при скрытом
  окне программы).
- Запись пишется на диск кусками по ходу (раз в секунду), чтобы сбой программы не терял всю встречу.
- После «Стоп»: диалог «Сколько человек было на встрече, включая вас?» (необязательно, можно пропустить)
  → автоматический запуск расшифровки.
- Название встречи по умолчанию: «Встреча 25.09.2026 14:30», можно переименовать.

### 3.2 Импорт
- Кнопка «Импорт файла» и перетаскивание в окно. Форматы: всё, что читает ffmpeg (mp3, m4a, wav, ogg, opus,
  flac, mp4, mov, webm, mkv…).
- Из видео извлекается только звук; сам видеофайл не копируется.
- Импорт = одна дорожка → «Я» не выделяется, по голосам делятся все участники.

### 3.3 Расшифровка (локально, после встречи)
- Модели — **каталог** ([решения Плана 7](2026-10-02-textmeet-plan-7-design.md) §3), все работают на процессоре
  через sherpa-onnx; ускорение на видеокарте — будущий план:
  - **GigaAM v3** (по умолчанию, «Рекомендуется») — русский, с пунктуацией и заглавными буквами. Английские слова
    пишет кириллицей — известное ограничение.
  - Понимают русский: **Parakeet v3**, **Qwen3-ASR 0.6B**, **Whisper large-v3-turbo**, **Nemotron 3.5**, **T-one**.
  - Только английский (для встреч на английском): **Parakeet Unified EN 0.6B**, **Canary 180M Flash**.
- Каталог — раздел настроек «Расшифровка»: карточки с языками, размером, полосками «точность» и «скорость»,
  «Скачать» / «Отменить» / «Удалить». Выбранная в настройках модель — для новых встреч; в окне «Расшифровать» /
  «Расшифровать заново» модель выбирается для одной встречи. Нескачанная модель скачивается при первой расшифровке с
  прогрессом.
- Во встрече подписано, какой моделью сделан текст («Текст: GigaAM v3»).
- Разметка спикеров:
  - дорожка микрофона → **«Я»**;
  - дорожка системного звука → разделение по голосам: **«Спикер 1», «Спикер 2», …**;
  - запись без системного звука или импорт → разделение по голосам всей записи, все — «Спикер N».
- Подсказка числа участников: если указано N человек «включая вас», то для дорожки системного звука
  число кластеров = N − 1 (для двоих разделение не нужно — всё на дорожке системного звука «Спикер 1»); для одной
  дорожки = N. Не указано — число определяется собственной группировкой «отпечатков голоса» (eres2net), а не
  порогом библиотеки ([решения Плана 3](2026-09-29-textmeet-plan-3-design.md) §4.4).
- Расшифровка ставится в очередь из окна «Запись остановлена» и по «Расшифровать», и по «Пропустить»; встреча без
  ответа (окно закрыто) расшифровывается по кнопке «Расшифровать» во встрече.
- Прогресс расшифровки виден в библиотеке; можно работать с другими встречами, пока идёт расшифровка.
- Повторная расшифровка встречи другой моделью / с другим числом участников (пока аудио не удалено).

### 3.4 Библиотека встреч
- Слева список встреч (название, дата, длительность, статус), сверху поиск.
- Справа выбранная встреча: реплики вида `[12:04] Иван: …`.
- Клик по реплике — воспроизведение записи с этого места; плеер с перемоткой.
- Правка текста реплик прямо в окне (сохраняется автоматически).
- Переименование спикера: клик по «Спикер 2» → «Иван» — меняется во всей встрече.
- **Поиск по всем встречам**: результаты — встреча + реплика + время; переход к найденному месту. Регистр и «ё/е»
  не различаются. Ищет по тексту реплик, названиям и ИИ-итогам.
- Кнопки: «Удалить аудио» (текст остаётся) и «Удалить встречу» — оба действия с подтверждением и **в Корзину**.
- «Скопировать всё», «Сохранить как…» → **.txt** или **.docx** (в .docx: имена спикеров жирным, время серым,
  ИИ-итоги — в начале документа, если они есть).

### 3.5 ИИ
- **«Скопировать для ИИ»** — копирует расшифровку + готовый запрос в буфер обмена (без API, бесплатно).
- **Подключение по API** (необязательно): Claude (Anthropic) или ChatGPT (OpenAI). Ключ вводится в настройках.
  - Кнопка **«Итоги встречи»** — стандартный отчёт: краткое содержание (3–5 пунктов), решения,
    задачи (кто / что / срок), открытые вопросы. Текст запроса редактируется в настройках; тот же текст
    использует «Скопировать для ИИ».
  - Поле **«Свой запрос»** — произвольный вопрос к встрече («что говорили про бюджет?»).
  - Запуск **только по кнопке**, ничего не отправляется автоматически.
  - Ответ показывается по мере генерации и сохраняется вместе со встречей; попадает в поиск.
  - Модель выбирается в настройках. По умолчанию для Claude — `claude-opus-5`; для OpenAI — актуальная
    флагманская модель, уточняется при реализации.

### 3.6 Настройки
Папка библиотеки · каталог моделей расшифровки (выбор, скачивание, удаление, размер) · микрофон · горячая клавиша
записи · звук при старте/стопе · запуск при входе в систему · ИИ-провайдер, ключ, модель · текст стандартного запроса ·
общие модели (разделение по голосам и поиск речи: размер, удалить).

### 3.7 Интерфейс
Русский язык. Светлая/тёмная тема — по системе. Макет утверждён 2026-09-28:
[Макет TextMeet](https://claude.ai/artifact/Urmc3atvSFifUpDyBzjeR6), стиль «Бумага»; решения —

## 4. Сознательно НЕ входит в первую версию

- Текст в реальном времени во время встречи.
- Автоопределение начала созвона.
- Узнавание людей по голосу между разными встречами.
- Чат со встречей, набор шаблонов ИИ-запросов.
- Подпись приложения, нотаризация, автообновление, установщик «для всех».
- Подавление эха: без наушников на дорожку «Я» попадут голоса собеседников из колонок (рекомендация — наушники).
- Экспорт в Markdown и субтитры (.srt).
- Облачная расшифровка.

## 5. Архитектура

### 5.1 Технологии
- **Electron + TypeScript**, сборка через electron-vite, интерфейс на React.
- **sherpa-onnx-node** (1.13.x): все модели расшифровки из каталога (GigaAM v3 и другие, на процессоре), Silero VAD
  (поиск речи), разделение по голосам (pyannote segmentation + модель «отпечатков голоса»).
- **ffmpeg** (встроенный бинарник): декодирование, конвертация в 16 кГц моно, сведение дорожек для прослушивания.
- **@anthropic-ai/sdk** и **openai** — ИИ-итоги.
- **docx** (npm) — экспорт в Word.
- **zod** — проверка всех файлов с диска и ответов извне.
- electron-builder: `.exe` (NSIS) для Windows x64 и `.dmg` для macOS arm64, без подписи.

### 5.2 Процессы

```
┌───────────────────────── Main process ─────────────────────────┐
│ окна, трей, IPC, настройки, ключи (safeStorage),              │
│ библиотека (файлы встреч), поисковый индекс в памяти,          │
│ менеджер моделей (скачивание), очередь задач расшифровки,      │
│ ИИ-клиенты, экспорт                                            │
└──────┬──────────────────┬──────────────────────┬───────────────┘
       │ IPC              │ IPC                  │ utilityProcess
┌──────▼───────┐  ┌───────▼────────┐  ┌──────────▼──────────────────┐
│ UI window    │  │ Recorder window│  │ Transcription worker        │
│ (React)      │  │ (скрытое окно) │  │ ffmpeg → VAD → диаризация →  │
│ библиотека,  │  │ getUserMedia + │  │ ASR (модель из каталога,    │
│ плеер, поиск │  │ системный звук │  │ sherpa-onnx в процессе)     │
│ настройки    │  │ → куски на диск│  │ → transcript.json           │
└──────────────┘  └────────────────┘  └─────────────────────────────┘
```

- **Recorder window** — отдельное скрытое окно, чтобы запись не зависела от перезагрузки/закрытия UI.
- **Preload** — один скрипт на оба окна (`src/preload/index.ts`): preload в песочнице не может подключать другие
  файлы, а общий код двух preload-скриптов сборщик выносит в отдельный файл. Какое окно каким каналом IPC может
  пользоваться, проверяет main по отправителю (`event.sender`); входные данные из окон проверяются zod.
- **Transcription worker** — отдельный процесс, чтобы тяжёлые вычисления и возможные падения нативного кода
  не вешали и не роняли интерфейс. Main перезапускает worker при падении и помечает задачу как «ошибка».

### 5.3 Захват звука
- **Микрофон:** `getUserMedia` в Recorder window, эхоподавление и шумоподавление браузера **выключены**
  (они портят распознавание и могут «съесть» речь).
- **Системный звук, Windows и macOS — один рецепт** (проверен на спайке, см.
  [итоги спайка](../spike-results.md), вариант Г):
  ```js
  // main
  session.setDisplayMediaRequestHandler((request, callback) =>
    callback({ video: request.frame, audio: 'loopback' }));
  // Recorder window
  navigator.mediaDevices.getDisplayMedia({
    video: { width: 320, height: 240, frameRate: 1 },
    audio: { restrictOwnAudio: true, echoCancellation: false, noiseSuppression: false,
             autoGainControl: false, channelCount: 2 },
  });
  ```
  Видеодорожка сразу отбрасывается. Источник — `request.frame`, **не экран**: с источником-экраном macOS
  отвечает AbortError «Invalid capture constraints».
  - **Windows:** `restrictOwnAudio` включает захват процессов (process loopback, Windows 10 build 20348+ /
    Windows 11): пишется весь звук, кроме звука самого TextMeet; не зависит от формата устройства вывода
    (захват всего устройства падал с NotReadableError на гарнитуре 7.1). Уровень зависит от системной громкости.
  - **macOS:** Chromium пишет системный звук через Core Audio Tap (разрешение «Запись системного звука»,
    ключ `NSAudioCaptureUsageDescription` в Info.plist). Нужна ли ещё «Запись экрана» — в Плане 2 не выяснено: запись на Mac работает, но какие окна разрешений
    показала система, не записано ([проверки Плана 2](../plan-2-checks.md)); перепроверить при чистой установке.
  - **Самопроверка:** NotReadableError / AbortError из `getDisplayMedia` → понятное сообщение
    «Не удалось захватить звук компьютера» с причиной; запись микрофона при этом продолжается.
  - Запасной путь (только если рецепт перестанет работать) — маленький помощник на Core Audio Taps (macOS) /
    WASAPI (Windows), отдающий PCM в main через stdout.
- **Запись на диск:** `MediaRecorder` (WebM/Opus) по каждой дорожке, кусок раз в секунду → main дописывает в файл.
  Время старта каждой дорожки фиксируется для выравнивания.
- **Индикаторы уровня:** `AnalyserNode` → уровни в UI ~15 раз/с.

### 5.4 Конвейер расшифровки (worker)

0. **Сразу после остановки записи / импорта** (ещё до расшифровки) main создаёт `mix.opus` — сведение дорожек
   для прослушивания, чтобы запись можно было слушать даже при ошибке расшифровки.
1. **Подготовка:** ffmpeg → каждая дорожка в 16 кГц моно float32.
2. **Дорожка «Я» (микрофон):** VAD → сегменты речи (≤ 20 с, резка по паузам) → ASR → реплики «Я».
3. **Дорожка собеседников / единственная дорожка:** сначала VAD (тишина — дорожка пропускается); для двоих
   участников разделения нет — вся речь «Спикер 1»; иначе диаризация (число кластеров из подсказки или собственная
   группировка «отпечатков голоса») → ходы без наложений → речь между ходами (VAD) отдаётся ближайшему спикеру →
   склейка соседних ходов одного спикера → резка до ≤ 20 с по самому тихому месту → ASR → реплики «Спикер N»
   (нумерация по первому появлению в итоговом тексте). Подробно — [решения Плана 3](2026-09-29-textmeet-plan-3-design.md) §4.
4. **Слияние:** реплики обеих дорожек сортируются по времени начала → `transcript.json`.
5. Прогресс (этап + %) отправляется в main → UI.

**Интерфейс движка распознавания** (одинаковый для всех моделей каталога; конвейер выше от модели не зависит):
```ts
interface Recognizer {
  recognize(samples: Float32Array): string;           // кусок ≤ 20 с, 16 кГц моно
}
```
- Модель расшифровки — id из каталога (`shared/asr-models.ts`, по умолчанию `gigaam-v3-e2e-rnnt`): он хранится в
  настройках (`asrModel`), в `meeting.json` (`model`) и в `transcript.json` (`model` и название `modelTitle`).
  Неизвестный id читается как GigaAM v3 (у встречи — с записью в журнал). Настройки sherpa-onnx для каждой модели — чистые данные
  (`main/transcription/asr-config.ts`); подробно — [решения Плана 7](2026-10-02-textmeet-plan-7-design.md) §4–5.
- Все модели — в worker через sherpa-onnx на процессоре: `OfflineRecognizer` (transducer, Qwen3-ASR, Whisper, Canary)
  или потоковый `OnlineRecognizer` (T-one, Nemotron: кусок подаётся целиком с запасом тишины). Worker держит одну
  модель расшифровки; у многоязычных моделей язык закреплён (русский у Qwen3-ASR, Whisper и Nemotron, английский у
  Canary).
- GigaAM — вариант **e2e_rnnt** (решение спайка: текст заметно чище e2e_ctc при почти той же скорости, RTF ≈ 0,13 на
  процессоре).
- Диаризация — модель отпечатков голоса **eres2net** (`3dspeaker_speech_eres2net_sv_en_voxceleb_16k`):
  разделяет собеседников заметно лучше titanet. Подсказка числа участников рекомендуется (диалог после «Стоп»);
  без неё число находит собственная группировка (порог библиотеки для этого непригоден: 0,5 дал 58 спикеров на
  записи с двумя).
- sherpa-onnx внутри Electron: во все вызовы, возвращающие массивы (`readWave`, `vad.front` и т. п.),
  всегда передавать `enableExternalBuffer = false` — иначе ошибка «External buffers are not allowed».
- Защита от выдуманных фраз на шуме («Продолжение следует…», зацикливание) — у Whisper и Qwen3-ASR
  ([решения Плана 7](2026-10-02-textmeet-plan-7-design.md) §4.3, [проверки Плана 7](../plan-7-checks.md)).

### 5.5 Модели
- Реестр моделей в коде (`main/models/registry.ts`): группы файлов — по одной на модель каталога и общая «voices»
  (поиск речи и разделение по голосам); у каждого файла URL, размер, SHA-256.
- Скачивание в служебную папку вне облака: Windows `%LOCALAPPDATA%\TextMeet\models`,
  macOS `~/Library/Application Support/TextMeet/models`, по папке на модель. Докачка после обрыва, проверка SHA-256.
  Скачивается только то, что нужно: модель из карточки каталога (одна за раз, с отменой) или модель встречи при
  расшифровке, плюс общие модели, если их нет.
- Источники — по каталогу ([решения Плана 7](2026-10-02-textmeet-plan-7-design.md) §3), адреса Hugging Face
  закреплены на коммите:
  - GigaAM v3 — ONNX для sherpa-onnx с Hugging Face (`Smirnov75/GigaAM-v3-sherpa-onnx`, MIT;
    `e2e_rnnt` int8 ≈ 311 МБ). Если источник пропадёт — сами конвертируем из официального
    `salute-developers/GigaAM` скриптами sherpa-onnx.
  - Остальные модели каталога — отдельные файлы с Hugging Face из зеркал автора sherpa-onnx (`csukuangfj`,
    `csukuangfj2`); архивы не нужны. Размеры — от 138 МБ (T-one) до 989 МБ (Whisper large-v3-turbo).
  - Silero VAD, модель отпечатков голоса (eres2net) — из релизов sherpa-onnx; pyannote segmentation — с Hugging Face
    (`csukuangfj`); вместе ≈ 32 МБ.

### 5.6 Хранение данных
Папка библиотеки по умолчанию: Windows `C:\Users\<user>\TextMeet`, macOS `~/TextMeet` (вне облака).
Меняется в настройках. **Никакого общего файла-базы**, у каждой встречи своя папка, чтобы синхронизация
через OneDrive не давала конфликтов:

```
<библиотека>/
  2026-09-25_1430_a1b2c3/
    meeting.json        # id, название, даты, длительность, источник (recording|import),
                        # подсказка числа участников, модель, статус, имена спикеров, schemaVersion
    transcript.json     # сегменты: id, start, end, speakerId, text, edited
    ai.json             # итоги и ответы на свои запросы: провайдер, модель, запрос, текст, дата
    audio/
      mic.webm          # дорожка микрофона (или source.webm для импорта)
      system.webm       # дорожка системного звука (если была)
      mix.opus          # сведение для прослушивания
```
- Все файлы пишутся атомарно (временный файл → переименование).
- Всё читаемое с диска проверяется по zod-схемам; повреждённая встреча показывается с пометкой, а не роняет
  программу.
- Настройки — JSON в папке данных приложения. **Ключи API** — отдельно, зашифрованы через Electron
  `safeStorage` (DPAPI на Windows, Связка ключей на macOS).
- **Поиск** — индекс в памяти, строится при запуске и обновляется при изменениях; повторное сканирование
  при возврате фокуса в окно (подхватывает встречи, пришедшие через OneDrive).

### 5.7 ИИ
- Провайдер Anthropic — официальный `@anthropic-ai/sdk`, стриминг, модель по умолчанию `claude-opus-5`.
- Провайдер OpenAI — официальный `openai` SDK, стриминг.
- В запрос уходят: системный промпт + расшифровка с именами спикеров и временем.
- Ошибки показываются по-человечески: неверный ключ, нет денег на счёте / лимит, нет сети, отказ модели.

## 6. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет разрешения на микрофон / системный звук | Понятное сообщение + кнопка «Открыть настройки системы» |
| Дорожка системного звука пуста (Mac: разрешение отозвано → трек молчит) | Предупреждение в окне записи, если с начала записи уровень ровно 0 дольше 10 с; исчезает, когда звук появился (на Windows тишина в созвоне — тоже ровный 0, поэтому только «с начала») |
| Сбой программы во время записи | При следующем запуске найденная незавершённая запись восстанавливается как встреча |
| Мало места на диске | Предупреждение перед стартом (< 1 ГБ) и во время записи |
| Горячая клавиша занята другой программой | Уведомление при запуске + предупреждение в настройках; запись по-прежнему доступна кнопкой и из трея |
| Модель не скачана / обрыв скачивания | Докачка, проверка SHA-256, кнопка «Повторить» (ошибки каталога моделей — [решения Плана 7](2026-10-02-textmeet-plan-7-design.md) §6) |
| Падение worker | Перезапуск worker, встреча помечается «Ошибка расшифровки» + «Повторить» |
| Повреждённый meeting.json | Встреча в списке с пометкой, остальное работает |
| Ошибка ИИ API | Сообщение с причиной, введённый запрос не теряется |

Ошибки пишутся в лог-файл в папке данных приложения (без текста встреч и без ключей).

## 7. Тестирование

- **Модульные (Vitest):** слияние реплик и диаризации, резка по паузам, расчёт числа кластеров,
  нормализация поиска (регистр, ё/е), форматирование .txt/.docx, чтение/запись встреч и схемы zod,
  переименование спикеров, реестр моделей. Цель — 80%+ покрытия логики.
- **Интеграционные:** конвейер расшифровки на коротком эталонном файле (`example.wav` из репозитория модели
  GigaAM, MIT) с реальными моделями; ИИ-клиенты — с подменой HTTP.
- **E2E (Playwright для Electron):** импорт файла → расшифровка → переименование спикера → поиск → экспорт →
  удаление.
- **Ручной чек-лист** для каждой ОС: запись созвона с системным звуком, запись без него, трей, сбой во время
  записи, разрешения на macOS, горячая клавиша поверх полноэкранного созвона, автозапуск после перезагрузки.
- **Модульные тесты** также на проверку и преобразование комбинации клавиш из поля настроек в формат Electron.

## 8. Сборка и поставка

- GitHub Actions: `windows-latest` → `.exe`; `macos-latest` (arm64) → `.dmg`. Модели расшифровки работают через
  sherpa-onnx, отдельная программа (whisper.cpp) не собирается; workflow `models-check` (по кнопке) проверяет все модели
  каталога на Windows, Mac и Linux.
- Сборка установщиков — по кнопке (workflow_dispatch) или по тегу, а не на каждый push: у закрытых
  репозиториев бесплатный лимит минут, а минуты macOS считаются с множителем.
- Без подписи: на Windows — «Подробнее → Выполнить в любом случае»; на Mac — «Открыть всё равно» в настройках
  безопасности. Инструкция в README.
