## Итог

На Windows всё работает. Во встрече — «Итоги встречи» и свои вопросы к ней: их пишет модель на компьютере
пользователя (без интернета, на видеокарте) через llama.cpp в составе программы. Модель выбирается и скачивается в
каталоге на вкладке «ИИ» (Qwen3.5 9B — рекомендуемая, Qwen3.5 4B, GigaChat 3.1 Lightning, T-lite-it 2.1). Итоги и
ответы сохраняются в `ai.json` встречи, ищутся поиском и попадают в начало выгрузки.

Следующий по дорожной карте — **План 8** (доводка).

Mac проверен на версии 1.0.0 ([проверки Плана 8](plan-8-checks.md)).

## Найдено проверками кода и исправлено (каждое — с тестом)

### Ревью прототипа (Task 6)

- Запуск движка, отменённый выходом из программы или удалением модели, не оставляет `llama-server` работать после
  выхода; «Итоги встречи» во время выхода ничего не запускает.
- «Удалить» модель и новый запрос не мешают друг другу: движок завершается до удаления файла (Windows не даёт удалить
  открытый), новые запросы до конца удаления получают «занято».
- Удаление встречи, пока запрос по ней только готовится, — запрос не начинается.
- После «Остановить» во время «Готовим модель…» и истёкшего времени загрузки следующий запрос запускает движок заново.
- «Итоги готовы» / «Ответ готов» — только для дописанного и сохранённого ответа.
- Ключ движка — в переменной `LLAMA_API_KEY`, а не в строке запуска; разбор потока не цитирует ответ модели в журнал.
- Отпечаток текста встречи — только участники и реплики (часовой пояс и длительность пометку «текст меняли» не дают).
- `npm run dev` / `start` без интернета не падают из-за движка.

### Итоговое ревью ветки (2026-10-15)

- **Нумерованные списки не сбрасываются на «1.»**, если модель вставляет между пунктами вложенный пункт или строку
  продолжения (`1. … - … 2. …`) — в блоке, «Скопировать», «Скопировать всё», .txt и Word номера идут по порядку.
- **«Ответ готов» звучит для каждого ответа**, а не только для первого (строка для экранного диктора очищается, пока
  модель пишет).
- **«Итоги встречи» сразу после открытия встречи** (пока `ai.json` ещё читается) больше не заменяет сохранённые итоги
  без вопроса «Заменить итоги?» — программа сначала узнаёт, есть ли итоги.

## Отложено

Известные ограничения, названные в плане:

- Если сама программа упадёт (не выход), `llama-server` может остаться работать до перезагрузки или до «Диспетчера
  задач»; следующий запуск запустит второй сервер.
- Итоги, упёршиеся в предел длины ответа (2048 «кусочков»), сохраняются как дописанные, без пометки.
- Неудача запроса по встрече, с которой ушли до конца ответа, видна при следующем открытии этой встречи.
- «Остановить» в первые доли секунды (пока запрос готовится) не срабатывает — запрос начнётся; его можно остановить
  следом.
- Испорченный, но правильного размера файл модели даёт общее «Модель не смогла ответить…», а не «файл повреждён».
- Вложенное оформление (`**жирный *курсив* жирный**`) показывается со звёздочками; вложенные списки — отдельными
  списками (номера теперь сохраняются).
- В архиве llama.cpp для Windows нет файла лицензии самой llama.cpp (MIT) — только OpenMP.
- Скорость на Mac (M4, 16 ГБ) не замерена.

Найдено итоговым ревью, не исправлялось:

- «Занято» (модель удаляется, другой запрос готовится, программа закрывается) — блок открывается пустым, без
  объяснения; нужен новый текст на экране.
- На границе 5 минут простоя новый запрос в течение ≤ 2 с, пока прежний движок завершается, может запустить второй
  `llama-server`; `ready()` смотрит только на «вышел», не на «завершается».
- Нет принудительного завершения движка, если он не вышел за 2 с (на Mac — SIGTERM; на Windows завершение и так
  жёсткое).
- После сохранения ответа на один обмен с main видны прежние итоги (короткое мелькание).
- Удаление встречи останавливает её ответ, даже если само удаление затем не удалось.
- Сквозной тест выхода во время ответа не проверяет, что процесс движка исчез; `test:llm` не проверяет, что сервер без
  ключа отвечает 401.
- Пока блок итогов свёрнут, «Ответ готов» не звучит.

Решения, принятые при выполнении:

- Кавычки в текстах — «ёлочки», как во всей программе (в решениях местами „лапки“).
- Испорченный или более новый `ai.json` при новых итогах заменяется без копии (решения Плана 9, §5).
- Падение движка посреди ответа — написанное не сохраняется, показывается причина и «Повторить» (решения, §6).
- В журнал при ошибке сервера попадает до 500 знаков его ответа (сервер не повторяет в ошибках текст встречи).
- Жёсткая ссылка на модель между дисками C: и D: невозможна — для ручной проверки модель скопирована.

Пункты «Отложено» Планов 3–7 и вопрос про «Запись экрана» на Mac ([проверки Плана 2](plan-2-checks.md)) остаются на
План 8.
