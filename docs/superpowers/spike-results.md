предлагать; порог авто-режима подбирается в плане расшифровки (План 3).

## 3. Системный звук (Task 10, 12)

Во всех вариантах — `session.setDisplayMediaRequestHandler` в main и `getDisplayMedia` в окне;
видео `{ width: 320, height: 240, frameRate: 1 }`. «Без обработки» =
`{ echoCancellation: false, noiseSuppression: false, autoGainControl: false, channelCount: 2 }`.
Варианты В, Г, Д добавлены в пробное приложение сверх плана после разбора неудачи на Windows.

| Вариант | Обработчик (`callback`) | `audio` в `getDisplayMedia` | Windows | macOS 27 |
|---|---|---|---|---|
| А — через экран | `{ video: sources[0] (экран), audio: 'loopback' }` | `true` | **нет:** NotReadableError | **нет:** AbortError «Invalid capture constraints» |
| Б — без экрана | `{ video: request.frame, audio: 'loopback' }` | `true` | **нет:** NotReadableError | **да:** 1 дорожка, `loopback`, моно 48 кГц, EC/NS/AGC включены, пик 1,000 (AGC / перегруз?) |
| В — через экран, без своего звука | как А | `restrictOwnAudio: true` + без обработки | **да:** `loopbackWithoutChrome`, 2 кан. 44,1 кГц, пик 0,058 | **нет:** AbortError «Invalid capture constraints» |
| Г — без экрана, без своего звука | как Б | `restrictOwnAudio: true` + без обработки | **да:** `loopbackWithoutChrome`, 2 кан. 44,1 кГц, обработка выкл., пик 0,026 | **да:** `loopbackWithoutChrome`, 2 кан. 48 кГц, обработка выкл., пик 0,682 (YouTube) |
| Д — без экрана, без обработки | как Б | без обработки, без `restrictOwnAudio` | **нет:** NotReadableError | **да:** `loopback`, 2 кан. 48 кГц, пик 0,817 |

Разрешения macOS: в раунде 1 система спросила все три — «Микрофон», «Запись экрана»,
«Запись системного звука». Нужна ли «Запись экрана» именно для варианта Г — не проверено отдельно
(см. открытые вопросы).

**Причина неудачи А/Б/Д на Windows:** устройство вывода по умолчанию — Logitech PRO X в режиме 7.1 (8 каналов).
Chromium 152 при захвате всего устройства (endpoint loopback) открывает WASAPI в 2 канала без
`AUTOCONVERTPCM` → `0x88890008 AUDCLNT_E_UNSUPPORTED_FORMAT` → NotReadableError. Родной WASAPI в 8 каналов
работает. С `restrictOwnAudio: true` Electron выбирает `loopbackWithoutChrome` — захват процессов
(process loopback, Windows 10 build 20348+ / Windows 11): пишется весь звук, кроме звука самого приложения;
от формата устройства не зависит. Уровень следует системной громкости (~−13,5 дБ относительно endpoint).

**Решение:** один рецепт для обеих ОС — **вариант Г**:
```js
// main
session.setDisplayMediaRequestHandler((request, callback) =>
  callback({ video: request.frame, audio: 'loopback' }));
// Recorder window
navigator.mediaDevices.getDisplayMedia({
  video: { width: 320, height: 240, frameRate: 1 },
  audio: { restrictOwnAudio: true, echoCancellation: false, noiseSuppression: false,
           autoGainControl: false, channelCount: 2 },
});
```
Swift-помощник на Core Audio Taps и родной WASAPI-помощник не нужны; остаются запасным путём.

## 5. Заметки для основного приложения

Из код-ревью спайка (`spike/src`):
- `audio.ts`: пик памяти ~3× от декодированного PCM (~1,3 ГБ на 2 ч) — декодировать потоком в заранее
  выделенный `Float32Array`.
- `download.ts`: у `fetch` нет тайм-аута и повторов, `.part` не удаляется при ошибке потока — нужны
  `AbortSignal.timeout`, повторы и очистка (плюс докачка и SHA-256 по спецификации).
- `pipeline.ts`: звук вне ходов диаризации молча теряется — прогонять VAD по промежуткам или помечать их.
- Перекрывающиеся ходы распознаются дважды (одна фраза у обоих спикеров) — обрезать или сливать перекрытия.
- Весь файл декодируется и диаризуется в памяти за один проход — нужна нарезка на куски или
  задокументированный предел длительности.
- `format.ts`: `formatTimestamp(NaN)` → `"NaN:NaN"` — проверять вход.
- `turns.ts`: `mergeTurns` — O(n²) (приемлемо на 1–3 тыс. ходов); через перебивания не склеивает (так задумано).
- Распознаватель типизирован как `any` — в приложении тонкий собственный интерфейс (`AsrEngine`).
- Уровень системного звука через process loopback зависит от системной громкости.
