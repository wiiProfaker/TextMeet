## Итог

Всё работает на обеих системах. Нативная часть sherpa-onnx на Mac грузится из `app.asar.unpacked` без
`DYLD_LIBRARY_PATH` (ревью задачи 1 сомневалось — снято).

Пользователь попросил выбор других моделей: Whisper для расшифровки, модели ИИ для итогов встречи и «предложи сам».
Решение: План 3 закрыть, выбор моделей расшифровки — следующим планом (План 7 переносится раньше Планов 4–6), выбор
модели ИИ — в Плане 6 (см. [дорожную карту](plans/2026-09-25-textmeet-roadmap.md)).

## Сделано сверх плана (по ревью кода, всё с тестами)

После каждой задачи код проверял отдельный ревьюер; исправления тоже проходили повторное ревью.

- **Число собеседников:** образцы для группировки берутся по всей встрече (самый длинный ход в каждом из 300 окон
  времени + 100 самых непохожих), а не 400 самых длинных — иначе на длинной встрече пропадал собеседник с короткими
  репликами. Размер группы по-прежнему считается только по образцам: подсчёт по всем ходам давал ложных спикеров на
  встречах 3–4 ч. Нулевые и нечисловые «отпечатки голоса» не участвуют.
- **Конвейер:** спикеры нумеруются по первому появлению в итоговом тексте (раньше — до выброса пустых реплик, могли
  быть «Спикер 2» без «Спикер 1»); тишина на дорожке собеседников не гоняется через разделение по голосам; прогресс
  всегда доходит до 100 %; если не прочиталась ни одна дорожка — в ошибке причины по каждой; последний кусок длинного
  хода не бывает крошечным.
- **Звук дорожки:** сторож зависшего ffmpeg (жёсткая остановка) и отмена.
- **Скачивание моделей:** остановка при лишних байтах, проверка `Content-Range` при докачке, запрос освобождается при
  любой ошибке, повторы восстанавливаются только при настоящем продвижении, отдельный текст для 403/404 сервера.
- **Менеджер моделей:** `verified.json` — только кеш (ошибка записи не мешает расшифровке); удаление и проверка моделей
  не идут одновременно; оценка места учитывает `.part` правильно.
- **Очередь:** после перезапуска — сначала прерванная встреча, затем ожидающие по времени постановки; встреча не
  расшифровывается дважды при повторном нажатии; нет ложных уведомлений «готово»/«ошибка» для снова поставленной
  встречи; сторож не остаётся взведённым; обратные вызовы окна не ломают очередь.
- **Процесс расшифровки:** модели грузятся один раз на процесс (раньше — на каждую встречу), держится только
  последняя копия каждой модели; процесс, остановленный до своего старта, не расшифровывает «вслепую»; ошибки процесса
  пишутся в журнал.
- **Тексты ошибок:** пользователю — простые русские фразы; сырые сообщения (пути, коды) — только в журнале.
- **Выход:** при выходе из Windows (завершение сеанса) расшифровка остаётся в очереди, а не помечается ошибкой;
  отменённое завершение работы на Mac не останавливает очередь; уведомление, если встречу не удалось поставить в
  очередь после «Запись остановлена»; щелчок по уведомлению не теряется, пока окно загружается.
- **Интерфейс:** при «Расшифровать заново» старый текст виден с узкой полоской хода над ним; «Расшифровываем…»
  вместо мигания «В очереди»; текст встречи не перерисовывается каждую секунду; «Расшифровать заново» — когда текст
  есть или расшифровка идёт; после неудачной повторной расшифровки можно выбрать другое число участников (кнопка в
  заголовке, «Повторить» — с прежним числом); доступность (роли, фокус после диалога, уникальные id); процент в
  списке не выходит за 0–100.
- **Тесты и CI:** запас времени для сквозных тестов на медленных машинах; открытые записи для тестов на настоящих
  моделях — в своей папке (`TEXTMEET_TEST_FIXTURES_DIR`), `ci.yml` кеширует её рядом с моделями; в тестовом режиме
  нет системных уведомлений.

## Отложено на следующие планы

- **План 4:** в `transcript.json` у реплик и спикеров неизвестные поля отбрасываются при чтении (сохраняются только
  на верхнем уровне), и запись текста не упорядочена по встрече — учесть, когда появится правка текста и
  переименование спикеров.
- **План 4:** открытый текст встречи не перечитывается, если `transcript.json` заменили снаружи при том же статусе —
  добавить номер правки при появлении правки.
- **План 8:** `TEXTMEET_TEST_ASR=fake` действует и в собранной программе (нужно для проверки сборки) — убрать или
  ограничить при доводке вместе с Electron fuses.
- Известное ограничение: на синтетической записи двух голосов длиной 3–4 ч без подсказки числа участников примерно в
  1 случае из 10 находится третий собеседник. С подсказкой (окно «Запись остановлена») этого нет.
- Известное ограничение: при смене числа потоков во время расшифровки (началась или закончилась запись) модель
  распознавания загружается заново — несколько секунд.
- Редкий случай: если встречу не удалось поставить в очередь из-за удалённой папки, уведомление всё равно говорит
  «запись сохранена» (причина — в журнале).
- Из Плана 2 по-прежнему открыт вопрос про «Запись экрана» на Mac ([проверки Плана 2](plan-2-checks.md)).
